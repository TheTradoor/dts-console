# Validation record

## Automated — 0.2.0

The clean-source run on 2026-11-04 passed 30 JavaScript tests and 21 Python
tests, with no failures or skips. Four complete firmware outputs and evidence
objects reproduced. See [the report](../dist/validation.json) and
[JavaScript TAP output](evidence/validation.tap).

The experimental parser matched both host decoders on 5,803 deterministic
vectors (1,805 accepted, 3,998 rejected). All 65,536 u16 declared lengths were
exercised separately. Selected paths also ran on the Python CPU core with bus
and stack tracing. Parser resources: 418 ROM bytes, 11 scratch bytes and two
stack bytes for the parser call; this is not a whole-firmware stack bound.

Correctly CRC-sealed unsupported messages were injected directly into the
emulator to bypass host validation and test the pre-sign gate. Other checks
cover unknown profiles, expected-key substitutions, input-envelope changes
after freezing, all invalid latch states and a blocked write to a locked bank.
See [FIRMWARE_POLICY.md](FIRMWARE_POLICY.md) for the precise scope.

Both fixture-result.json and nonce-fixture-result.json were generated by
executing the pinned 65C02 firmware on the upstream C emulator. The bridge
checked both bank locks, zero blocked writes, an unchanged frozen message, a
cleared emulated scratch region, the complete output record, an identical
OpenSSL signature, and successful OpenSSL verification.

The opt-in builds produce policy-fixture-result.json and
policy-nonce-fixture-result.json. Their 256-byte signed records match the
baseline byte for byte. Emulated cycles for these fixtures:

| Build | Legacy | Durable nonce |
| --- | --- | --- |
| Unmodified pinned ROM | 651,345,707 | 652,476,175 |
| Experimental parser ROM | 651,354,174 | 652,488,289 |

These cycle differences include changed code placement as well as parsing.
They are not physical signing times or general worst-case timing bounds.

These checks do not establish physical erasure, hardware isolation, side-channel
resistance, trusted device authorization, or successful on-chain execution.

## Historical browser checks — 0.1.0 interface

Completed in Chrome on the original 0.1.0 interface through the actual UI.
The 0.1.1 changes concern source pins, Python boundary validation, packaging
and documentation; these historical browser checks are not a new hardware test:

- Prepare the default 5,000-lamport fixture and decode all fields.
- Confirm export is disabled until all four recipient pages are visited and
  the user acknowledgement is checked.
- Verify the recorded 65C02 result in the browser.
- Change the amount to 6,000 lamports and confirm the old result is rejected
  as belonging to a different session.
- Review and export that new session through the browser download flow.
- Execute it with the actual pinned 65C02 firmware: 650,669,743 cycles,
  double-sign/verify retained, OpenSSL signature equality and verification.
- Import the downloaded session and fresh result through browser file pickers;
  the result visibly verified for exactly 6,000 lamports.
- Import a result with a modified signature byte; the browser rejected its CRC.
  Automated tests also reject a modified signature after its CRC is recomputed.
- Inspect the desktop layout and a real 390-by-844 CSS iframe viewport.
  Mobile document width and scroll width both measured 375 CSS pixels
  (390 pixels including the scrollbar), with no horizontal overflow.

The local preview uses HTTP. Portable verification was added because WebCrypto
is unavailable in that context; automated tests cross-check the portable
implementation against the platform provider, including a no-WebCrypto case.

The original JavaScript run passed 28 tests. The current recorded validation
includes the independent Python suite and four fresh full firmware executions;
use ../dist/validation.json for its actual counts and timestamp.
Manual browser checks and historical upstream tests are not added to that count.

## Source-pin correction in 0.1.1

The earlier preparation copy appended one newline to each of the eight source
files. Its hashes therefore did not match a clean upstream download. The source
lock now hashes the exact raw bytes, verified against GitHub Git blob IDs at
the pinned commit. No upstream executable statement was changed. Both recorded
firmware outputs must reproduce unchanged after this correction.

The Python host validator also now rejects boolean false as profile 0 rather
than relying on Python's equality between false and numeric zero.

The clean-fetch check also exposed four missing transitive imports: the
assembler imports cpu65c02, which imports timing, engine and parts. All four
are now fetched and pinned, making the manifest cover twelve source files.
Reproduction uses only this downloaded source closure.
